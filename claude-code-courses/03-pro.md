# Курс 3. Claude Code: Профи (продвинутый уровень)

## 1. Паспорт
- **Аудитория:** тимлиды, senior-инженеры, DevOps, архитекторы, CTO, интеграторы ИИ-решений.
- **Вход:** курс «Практик» или уверенный опыт с Claude Code, git, CI.
- **Результат:** мультиагентные процессы, интеграция в CI/CD, собственные агенты на SDK, политика безопасности, расчёт ROI, внедрение в команде.
- **Формат:** 8 недель × 3 урока + проектная работа + менторские созвоны. Офлайн: 3 дня. Корпоративная версия: пилот на 4–6 недель.

## 2. Программа

### Модуль 1. Архитектура агентной разработки (неделя 1)
**1.1. Модель работы агента:** цикл «рассуждение → инструмент → наблюдение», где ломается качество, контекст как ресурс.
**1.2. Паттерны:** orchestrator-worker, ревьюер-исполнитель, параллельные ветки, «планировщик + исполнитель». Когда агентов больше — хуже.
**1.3. Спецификация перед кодом:** spec-driven подход, критерии приёмки, тесты как контракт.

### Модуль 2. Субагенты и параллелизм (неделя 2)
**2.1. Проектирование субагентов:** `.claude/agents/*.md`, описание, ограничение инструментов, модель под задачу.
**2.2. Параллельная работа:** worktrees, разделение задач без конфликтов, слияние результатов `[СВЕРИТЬ]`.
**2.3. Контроль качества:** агент-ревьюер, независимая проверка, адверсарное тестирование.

### Модуль 3. Расширения уровня платформы (неделя 3)
**3.1. Skills как корпоративная база знаний:** версионирование, тестирование, ресурсы.
**3.2. Плагины и маркетплейсы:** упаковка набора команд/агентов/хуков/MCP в плагин, внутренний каталог `[СВЕРИТЬ]`.
**3.3. Свои MCP-серверы:** создание MCP-сервера для внутренней системы, авторизация, аудит.

### Модуль 4. Хуки и guardrails (неделя 4)
**4.1. Хуки как политика:** блокировка опасных операций, обязательные проверки, логирование всех действий.
**4.2. Управляемые настройки:** централизованные политики на организацию `[СВЕРИТЬ]`.
**4.3. Prompt injection и модель угроз:** векторы атаки, эксфильтрация, изоляция, песочницы, принцип наименьших привилегий. Практика: red-team своего агента.

### Модуль 5. CI/CD и автоматизация (неделя 5)
**5.1. Headless и GitHub Actions:** `claude -p`, action для PR-ревью, issue → PR `[СВЕРИТЬ]`.
**5.2. Пайплайны:** автотесты, автофикс линтеров, генерация release notes, миграции.
**5.3. Надёжность:** ретраи, лимиты, идемпотентность, человек в контуре, стоп-кран.

### Модуль 6. Agent SDK (неделя 6)
**6.1. Знакомство с SDK (Python/TypeScript):** запуск агента из кода, потоковый вывод, свои инструменты `[СВЕРИТЬ]`.
**6.2. Продуктовые агенты:** поддержка, ревью документов, аналитик данных, DevOps-бот.
**6.3. Наблюдаемость:** логи, трассы, оценка качества, регрессионные наборы задач (evals).

### Модуль 7. Стоимость, масштаб, ROI (неделя 7)
**7.1. Экономика:** токены, кэширование, выбор моделей, бюджеты на команду.
**7.2. Метрики эффекта:** время цикла, % принятых PR, число инцидентов, удовлетворённость разработчиков.
**7.3. Бизнес-кейс:** как посчитать окупаемость и презентовать руководству.

### Модуль 8. Внедрение и финал (неделя 8)
**8.1. Change management:** пилот → стандарты → обучение → масштабирование.
**8.2. Стандарты команды:** шаблон репозитория, чек-листы, Definition of Done для работы с агентом.
**8.3. Защита итогового проекта.**

## 3. Итоговый проект (выбрать один)
A. **Агентный конвейер для реального репозитория:** issue → план → реализация → тесты → ревью другим агентом → PR, с guardrails и метриками.
B. **Продуктовый агент на SDK:** с инструментами, логированием, evals, документацией.
C. **Корпоративный стандарт внедрения:** плагин, политика безопасности, обучающий план, бизнес-кейс.

| Критерий | Баллы |
|---|---|
| Архитектура и обоснование паттернов | 20 |
| Безопасность и guardrails | 20 |
| Надёжность и воспроизводимость | 20 |
| Метрики/evals/ROI | 20 |
| Документация и передаваемость | 10 |
| Защита | 10 |
Зачёт ≥ 80 → сертификат Pro.

## 4. Экзаменационные кейсы
1. Агент удалил ветку: расследуйте, какие guardrails должны были сработать.
2. В репозиторий проник вредоносный README с инструкциями: спроектируйте защиту.
3. Бюджет на агентов вырос в 3 раза: найдите причины и оптимизируйте.
4. Агент-ревьюер пропускает ошибки: как улучшить через evals?

## 5. Руководство преподавателя
- Преподаватель — практикующий инженер: нужен собственный production-опыт, иначе курс потеряет ценность.
- Все модули — на реальных кодовых базах участников (с NDA) или на тренировочном «грязном» репозитории.
- Акцент: управляемость, воспроизводимость, безопасность. Не «магия».
- Менторские сессии: 30 мин на участника после модулей 3, 5, 7.

## 6. Офлайн-интенсив (3 дня, до 12 человек)
**День 1 — Архитектура и безопасность:** паттерны, субагенты, хуки, модель угроз, red-team практикум.
**День 2 — Автоматизация:** CI/CD, headless, GitHub Actions, свои MCP/плагины, надёжность.
**День 3 — SDK, метрики, внедрение:** Agent SDK, evals, ROI, защита проектов, дорожная карта для вашей компании.
Расписание каждого дня: 10:00–13:00 теория+демо, 14:00–18:00 практикум, 18:00–19:00 разбор.

Оборудование: ноутбуки, тестовый org-репозиторий на GitHub, тестовые токены, сервер/песочница для CI, проектор, 2 ассистента.

## 7. Корпоративная версия
1. Аудит процессов (1–2 дня).
2. Пилот на 1 команде (4–6 недель) с метриками «до/после».
3. Обучение (курс Практик + Профи).
4. Корпоративный плагин и политика безопасности.
5. Поддержка 3 месяца.

## 8. Комплект упаковки
24 видеоурока, шаблон монорепозитория с агентами/хуками/плагином, CI-пайплайны, набор evals, шаблон политики безопасности, шаблон бизнес-кейса, чек-листы, сертификат Pro, закрытое сообщество.
