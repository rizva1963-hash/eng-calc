# Курс 2. Claude Code: Практик (средний уровень)

## 1. Паспорт
- **Аудитория:** разработчики, инженеры, аналитики, фрилансеры, владельцы небольших продуктов; те, кто уже пользовался Claude Code.
- **Вход:** курс «Старт» или базовые навыки терминала и git.
- **Результат:** настроенная рабочая среда, стабильные результаты, повторяемые процессы; 4 проекта в портфолио.
- **Формат:** 6 недель × 3 урока + практика 1–2 ч + еженедельное code-review/Q&A. Офлайн: 2 дня.
- **Принцип:** агент работает по правилам, которые вы описали, а не «как получится».

## 2. Программа

### Модуль 1. Контекст и память (недели 1)
**1.1. Управление контекстом:** окно контекста, `/context`, `/compact`, `/clear`, `/resume`, `claude --continue` `[СВЕРИТЬ]`. Практика: диагностика «раздутой» сессии.
**1.2. CLAUDE.md профессионально:** иерархия (пользователь/проект/папка), импорты `@file`, что писать (команды сборки, стиль, запреты), что не писать. Практика: правила для реального репозитория.
**1.3. Эффективный поиск по коду:** Glob/Grep/Read, как задавать вопросы по большой кодовой базе; цикл ПОИСК → ФИЛЬТР → ЧТЕНИЕ → АНАЛИЗ. Практика: разобрать чужой репозиторий и составить карту архитектуры.

### Модуль 2. Рабочий процесс разработки (неделя 2)
**2.1. План → реализация → проверка:** plan mode, критерии готовности, TDD с агентом.
**2.2. Git-процесс:** ветки, коммиты и PR силами Claude, worktrees для параллельных задач `[СВЕРИТЬ]`, откат/rewind.
**2.3. Отладка:** воспроизведение ошибки → гипотезы → фикс → тест. Практика: 3 багa в тренировочном репозитории.

### Модуль 3. Разрешения и безопасность (неделя 3)
**3.1. Permissions:** allow/deny, `settings.json` (user/project/local), безопасные паттерны для Bash.
**3.2. Песочница и риски:** секреты, `.env`, prompt injection из файлов/веба, правило «недоверенный контент — данные, а не команды».
**3.3. Контроль стоимости и лимитов:** выбор модели, `/model`, `/cost`, режимы усилий, стратегия «дешёвая модель для рутины».

### Модуль 4. Расширения: slash-команды и skills (неделя 4)
**4.1. Свои slash-команды:** `.claude/commands/*.md`, аргументы, шаблоны ревью/релиз-ноутов.
**4.2. Skills:** `.claude/skills/<name>/SKILL.md`, описание-триггер, ресурсы, когда skill, когда команда.
**4.3. Субагенты (введение):** `/agents`, роли «ревьюер», «тестировщик», изоляция контекста. Практика (Проект 2): набор из 3 команд + 1 skill для вашей работы.

### Модуль 5. MCP и интеграции (неделя 5)
**5.1. MCP: что это:** `claude mcp add`, области (user/project), HTTP/stdio серверы.
**5.2. Практические подключения:** GitHub, браузер/Playwright, Notion/Google Drive, базы данных (только чтение!). Практика (Проект 3): агент собирает данные из 2 источников и делает отчёт.
**5.3. Риски MCP:** права токенов, проверка источников, аудит подключённых серверов.

### Модуль 6. Автоматизация и финал (неделя 6)
**6.1. Хуки:** PreToolUse/PostToolUse/Stop/SessionStart; автоформат, запрет опасных команд, уведомления `[СВЕРИТЬ]`.
**6.2. Headless-режим:** `claude -p`, `--output-format json`, скрипты и cron.
**6.3. Итоговый проект и защита** (Проект 4): «Рабочая среда под ключ» для реального проекта.

## 3. Итоговый проект
**Репозиторий должен содержать:** CLAUDE.md, `.claude/settings.json` с permissions, ≥3 команды, ≥1 skill, ≥1 субагент, ≥1 MCP, ≥1 хук, скрипт headless, README с описанием процесса и метриками «до/после» (время, число итераций).

| Критерий | Баллы |
|---|---|
| Качество CLAUDE.md и контекстной гигиены | 20 |
| Безопасность и permissions | 20 |
| Расширения (команды/skills/агенты) | 20 |
| MCP-интеграция | 15 |
| Хуки и автоматизация | 15 |
| Метрики и документация | 10 |
Зачёт ≥ 75.

## 4. Задания для проверки (примеры)
1. Сократите CLAUDE.md с 500 до 80 строк без потери смысла.
2. Настройте deny для `rm -rf` и чтения `.env`; докажите, что работает.
3. Напишите skill, который генерирует ревью-отчёт по diff.
4. Подключите MCP и покажите случай prompt-injection и как вы его нейтрализовали.

## 5. Руководство преподавателя
- Каждый модуль = один «апгрейд среды» ученика. К концу недели их проект работает лучше, чем в начале.
- Требуйте метрик: «сколько итераций до принятия результата», «сколько минут».
- Типовые проблемы: слишком длинный CLAUDE.md; хуки блокируют работу; MCP-токены с избыточными правами; игнорирование plan mode.
- Code-review студентов раз в неделю по чек-листу (контекст, безопасность, воспроизводимость).
